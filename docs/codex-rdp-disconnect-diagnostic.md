# One-shot RDP disconnect diagnostic

This is a dedicated diagnostic, **not** an orchestration task. It never calls `invoke-codex-interactive.ps1` and does not change the production Gateway/S4U configuration. It uses a separate `C:\work\ai-workspace-logs\codex-rdp-disconnect-diagnostic` queue and fixed `diag-rdp-disconnect-once` identity. No caller arguments can change the repository (`C:\work\pve-doc`), executable, Codex arguments, prompt, or duration. The worker runs Codex with `-a never`, `exec -s read-only --ephemeral -`. The queue is one-shot; do not delete it to retry an unknown result.

**Before starting:** `pnpm build` must have completed. The already-running worker does not load new code from disk: arrange an approved restart of **only the Interactive worker**, then confirm `scripts/status-ai-workspace-gateway.ps1` reports a fresh PID, SessionId > 0 and heartbeat. The start command refuses an old worker protocol. Do not restart the production Gateway. Verify the diagnostic log directory does not already exist and review its ACL (trusted workspace account and Administrators only). Run from an elevated workspace RDP shell in the **same SessionId** as the worker.

1. Start once: `pwsh -NoProfile -File .\scripts\run-codex-rdp-disconnect-diagnostic.ps1 -Start`. Wait for **"Codex started"**; note the baseline worker PID/SessionId and Codex PID. At that message, close/disconnect the RDP window **without logging off**. Do not run `-Start` a second time.
2. Reconnect after **10–12 minutes** (allow time for the post-hold Codex reads). Run `pwsh -NoProfile -File .\scripts\run-codex-rdp-disconnect-diagnostic.ps1 -Status`. If still running, repeat **only `-Status`** after a short wait. Read `summary.json`, `stdout.log`, `stderr.log`, `codex-started.json`, `prompt-sent.json`, and `observations.jsonl` in the dedicated log directory. `-Status` does not enqueue work.
3. PASS requires the same live worker PID/SessionId, approximately 2-second continuous worker observations for the ten-minute hold, Codex alive across the hold, a fixed prompt sent at least 600 seconds after Codex start, matching result identity, exit code 0, four successful read command traces, and no runner pipe timeout or `0xc0000142`. Compare the operator-recorded disconnect/reconnect time against the observation timestamps; worker self-observations alone **cannot prove the RDP connection was closed**.

For a **read-only reevaluation** of saved evidence, run the script with `-Review` instead of `-Status`. This does not write `summary.json`, `stdout.log`, or `stderr.log`, and never enqueues or reruns Codex. If the worker has since exited, review uses only the previously saved successful live-worker check tied to the same baseline and a heartbeat after completion; it labels this `worker_evidence: recorded_live_check`. Normal `-Status` still requires a live worker now. Read checks use the `exec` command/result blocks in Codex stderr plus the expected command outputs (not Codex's natural-language conclusion); concurrent command results need not be in command order. A failed or unmatched result does not count as a successful read.

The worker starts one fixed read-only Codex process before disconnection and holds its stdin open for ten minutes, then sends the fixed four-read prompt. This tests **process/session survival followed by a Codex task completing after disconnection**; it does **not** prove ten minutes of active model computation. A Codex failure or loss of observations is not a pass. The diagnostic has a 15-minute overall ceiling; no automatic retry or claim removal occurs. Production requests use their original queue and can continue independently.
